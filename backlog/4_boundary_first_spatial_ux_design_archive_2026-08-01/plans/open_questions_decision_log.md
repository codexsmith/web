# Open Questions and Decision Log

## Decisions already made

- Use an institutional, user-centered front door.
- Preserve one connected Atlas rather than separate sites for each audience.
- Treat claim status as a structural part of the UI.
- Make Corpus Forge a first-class product and institutional proof.
- Use a binding protocol to keep data and interface specification distinct.
- Embed the familiar scientific method within a broader lawful cycle.
- Treat spatial metaphors as operational bindings, not decoration.
- Preserve dense 2D workbench and accessible modes alongside immersion.
- Explore RTS interaction grammar but reject conquest and fake productivity incentives.

## High-priority open decisions

### D-001 — Canonical product name for the platform

Candidates:

- Corpus Forge;
- Boundary First Workbench;
- Boundary First Lab Environment;
- one umbrella platform with Corpus Forge as the research-production subsystem.

### D-002 — Semantic storage model

Options:

- relational core plus graph projection;
- graph-first object store;
- event-sourced relational/graph hybrid;
- file-first canonical Markdown/JSON with indexed projection.

### D-003 — Binding protocol authority

Determine whether bindings are:

- configuration only;
- reviewed product artifacts;
- canonical public specifications;
- executable policies with separate security review.

### D-004 — First sample inquiry

Candidate vertical slices:

- fine-structure constant research ledger;
- a bounded Millennium-problem proof attempt;
- Boundary First Labs public architecture;
- software invoice-approval case;
- a small materials-science literature corpus.

The first slice should be rich enough to exercise claims and contradictions but bounded enough to verify manually.

### D-005 — 2D client stack

Select based on current implementation constraints after the schema and interaction spec close.

### D-006 — Spatial renderer

Web-first versus native/game-engine prototype. Decision should follow the single-room task definition, not aesthetics alone.

### D-007 — Pointer terminology

Candidates:

- Boundary-Aware Spatial Pointer;
- Distinction-Space Cursor;
- Volumetric Interaction Field;
- Spatial Probe.

### D-008 — Degree of environmental persistence

Does the spatial room remember user-arranged artifacts, or is layout generated deterministically from semantic state and current task?

### D-009 — Collaboration model

How multiple humans and agents appear, reserve work, annotate shared state, and avoid edit conflict.

### D-010 — Public/private boundary

Which parts of Corpus Forge are public evidence surfaces, which are collaborator workspaces, and which are restricted founder/research operations?

## Research questions

- Does spatialization improve reasoning or primarily improve emotional engagement?
- Which epistemic relations benefit from physical metaphor, and which become misleading?
- Can candidate ranking remain transparent enough for trust?
- How does the system signal uncertainty without visual noise?
- How much of the RTS grammar transfers to slow, asynchronous research?
- What is the smallest useful binding language that does not become a full programming language prematurely?
- Can the same binding profile generate both accessible list views and immersive environments faithfully?
