## Current precedence

Architectural and copy decisions now have related but distinct authorities.

### Information architecture

When supporting artifacts conflict on page structure, navigation, public/deep layering, or front-door composition, use this order:

1. `README.md` — current public-front-door information architecture;
2. `STATUS.md` — current workstream ownership/status;
3. `process_machine_and_execution_trace_spec.md` — current Process architecture and future development rationale;
4. other supporting artifacts — retained design history and reusable material.

### Public copy and positioning

For homepage orientation language, belief burden, inherited-machinery framing, Method/Research/About introductions, Boundary Theory public role, Distinction Space public positioning, Schemathematics public positioning, and trust/claim language, use:

1. `product_owner_public_copy_systematization_reframe.md` — active product-owner direction;
2. current source-controlled Lab theory/terminology authority at implementation time — mathematical and claim-control source of truth;
3. existing live web content objects — preserve useful material where compatible, but do not let older wording override the reframe;
4. older supporting copy artifacts — retained as design/provenance material.

The product-owner copy document is deliberately downstream of the Lab's canonical theory. It governs **public projection and ordering**, not mathematical truth. If theory terminology changes before implementation, preserve the product principles while resolving exact technical wording against the current Lab authority.

In particular, the guided-tour concept no longer needs to carry the entire five-minute public explanation. The current direction is to let familiar machinery, flagship products, Timeline, Paper Mine, Research Lane, interactive instruments, and intake collectively explain the Lab, with the existing Lab Machine remaining behind **Enter the Lab**.

The public copy should now follow the broad sequence:

```text
familiar machinery
    -> recurring coordination problem
        -> Boundary First method
            -> Lab and concrete work
                -> research question
                    -> formal stack
                        -> evidence / results / failures
```

The site should not require a cold visitor to accept a novel foundational claim before understanding what BFL does.

## Current Process posture

The Lab-root **Timeline** remains a useful temporal projection.

The generic non-root **Process** control is intentionally hidden for now. Direct Process URLs and the underlying process-placement/circuit machinery remain available for inspection and later development.

The refined Process diagnosis is:

```text
Process Machine
= reusable Boundary First / Agentic Scientific Method operating grammar

Process Placement
= inferred or declared coordinate relative to that machine

Process Trace
= object-specific governed execution history through that machine
```

The current site has the first two and only a weak approximation of the third.

Future work should therefore preserve the generic machine, stop treating genericness itself as the primary defect, and build the missing trace substrate: recorded transitions, closure attempts, repair/reopen loops, artifacts crossing boundaries, evidence-triggered decisions, authority, promotion gates, and next admissible moves.

The intended longer-term composition is for Process Trace, Research Lane, Timeline, Evidence, and the Knowledge Transform Graph to reuse a shared governed event/transform substrate rather than maintaining incompatible workflow models.
