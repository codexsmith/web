# Tasks and Goals Roadmap

**Version:** 0.1  
**Planning horizon:** Immediate, 30-day, and 90-day  
**Primary objective:** Convert the conversation synthesis into one publishable doctrine, one testable operating protocol, and one purchasable service.

## Goal G1 — Establish the canonical framework

**Outcome:** Boundary First Labs has one stable account of consequence-bearing development and AI repair loops that is compatible with existing closure-driven work.

### P0 tasks

- [ ] **T1.1** Review `02_consequence_bearing_development.md` against *Closure-Driven Software Development*.
- [ ] **T1.2** Decide naming hierarchy:
  - Closure-Driven Software Development as existing parent/practitioner frame;
  - Consequence-Bearing Development as sharpened operating doctrine;
  - Bounded Consequence Circuit as protocol;
  - AI Repair Loop as machine-operable implementation.
- [ ] **T1.3** Resolve whether `Represent → Bound → Commit → Execute → Instrument → Observe → Compare → Repair → Verify → Close` is the canonical stage sequence.
- [ ] **T1.4** Promote protected distinctions and failure patterns into the corpus glossary.
- [ ] **T1.5** Record claim ceilings for social, evolutionary, and AI-autonomy statements.

### Closure criteria

- one approved naming stack;
- no conflict with existing canonical documents;
- all terms have definitions and relationships;
- claim ceilings are visible.

## Goal G2 — Produce the first public document product

**Outcome:** A publishable v0.1 of *The AI Repair Loop Playbook* and a usable template bundle.

### P0 tasks

- [ ] **T2.1** Expand `10_ai_repair_loop_playbook_outline.md` into a 6,000–9,000 word draft.
- [ ] **T2.2** Build one complete worked example, preferably a GitHub pull-request repair loop.
- [ ] **T2.3** Convert YAML templates into reader-friendly worksheets.
- [ ] **T2.4** Create two diagrams:
  - representational reinforcement versus consequential confirmation;
  - bounded AI repair-loop state machine.
- [ ] **T2.5** Add a two-page executive summary.
- [ ] **T2.6** Conduct internal red-team review for false autonomy, self-verification, and authority collapse.

### Closure criteria

- a coherent field guide can be read without prior Boundary Theory knowledge;
- every major claim has an example or test;
- the reader can instrument one bounded loop from the templates;
- AI cannot self-authorize or self-close in the proposed design.

## Goal G3 — Validate a sellable consulting offer

**Outcome:** One real buyer confirms the problem strongly enough to share a workflow, pay for an audit, or commit to a pilot.

### P0 tasks

- [ ] **T3.1** Refine `11_ai_consequence_loop_audit_offer.md` into a one-page PDF/web page later.
- [ ] **T3.2** Identify ten target contacts from prior consulting, insurance, public-sector, medical, or software networks.
- [ ] **T3.3** Conduct five problem interviews focused on actual AI verification and repair failures.
- [ ] **T3.4** Offer a tightly bounded pilot: one workflow, one consequence map, one implementation plan.
- [ ] **T3.5** Define pilot evidence before delivery: defects found, missing channels, false closures, repair ownership, implementation readiness.

### Closure criteria

At least one of:

- paid pilot;
- signed letter or email of intent;
- access to a real bounded workflow plus scheduled decision meeting;
- three independent buyers describe substantially the same expensive failure.

## Goal G4 — Build a reference implementation

**Outcome:** Demonstrate that the protocol works in software rather than only in prose.

### P1 tasks

- [ ] **T4.1** Select a small open or private repository with CI.
- [ ] **T4.2** Represent one issue as `templates/repair_job.yaml`.
- [ ] **T4.3** Implement an agent or scripted workflow that proposes a branch change.
- [ ] **T4.4** Use CI as the first independent consequence channel.
- [ ] **T4.5** Preserve evidence, discrepancy, repair, authorization, and closure records.
- [ ] **T4.6** Deliberately inject one defect that fluent review is likely to miss but tests expose.
- [ ] **T4.7** Produce a public-safe case study.

### Closure criteria

- reproducible repository or recorded demonstration;
- full audit trail;
- at least one detected mismatch and verified repair;
- documented case where AI output remained open until evidence returned.

## Goal G5 — Develop the research paper

**Outcome:** A defensible conceptual paper and research program, not an overclaimed civilizational thesis.

### P1 tasks

- [ ] **T5.1** Build a literature map across cybernetics, control, falsification, distributed cognition, institutional epistemology, human–AI interaction, automation bias, and AI delusion risks.
- [ ] **T5.2** Separate established findings from Boundary First interpretation.
- [ ] **T5.3** Define social-mediated and consequence-mediated functions formally enough to compare.
- [ ] **T5.4** Collect three software and three institutional case studies.
- [ ] **T5.5** Specify observable indicators of mediation superseding consequence.
- [ ] **T5.6** Submit the evolutionary framing to adversarial review before publication.

### Closure criteria

- citations support each nontrivial empirical statement;
- evolutionary language is explicitly qualified;
- the paper produces testable diagnostics, not only rhetoric;
- counterexamples and beneficial mediation functions are included.

## Goal G7 — Create Boundary First Labs operational infrastructure

**Outcome:** New claims and products pass through the same consequence-bearing discipline they advocate.

### P1 tasks

- [ ] **T7.1** Add claim contracts and closure records to Corpus Forge jobs.
- [ ] **T7.2** Require independent consequence channels for promoted AI-generated claims.
- [ ] **T7.3** Add failure-pattern checks to the Corpus Forge Critic.
- [ ] **T7.4** Track accepted-open risk and deferred repair obligations.
- [ ] **T7.5** Publish a negative-result and reopened-closure policy.

### Closure criteria

- AI synthesis is never its own independent verification;
- reopened claims remain traceable.
