# Original Visual Grammar: From Distinction to Consequence

**Document class:** Working public design and provenance note  
**Version:** v0.1  
**Promotion state:** Pending founder, research, and visual review

## Purpose

This visual set gives the **world class** and **executable distinctions** arguments a shared, inspectable grammar.

The diagrams are not ornamental summaries. Each one names a primary consequence path, the gate that tests the result, and the repair route that returns a defect to governable state.

Use the rendered [Original Visual Grammar](/language/visuals) for the complete accessible diagrams.

## Diagram 1: class to consequence

The first diagram follows this path:

```text
class
  -> instance
  -> state
  -> admissible operation
  -> consequence
  -> invariant check
```

If the invariant is preserved, the result may close or advance. If the invariant is broken or uncertain, the route continues through:

```text
witness
  -> responsibility
  -> repair and revision
  -> return to state
```

The diagram therefore treats **class** as a specification whose significance appears through concrete instances, reachable states, permitted operations, observed consequences, and the capacity to detect and repair failure.

It does not define a person as an object or equate an institution with a software program.

## Diagram 2: symbol to consequence

The second diagram follows this path:

```text
symbol
  -> interpreter or procedure
  -> recognized classification
  -> authority and standing gate
  -> admissible operation
  -> state transition
  -> consequence
  -> contestability check
```

If the classification, authority, or execution is contested, the route continues through appeal, witness, responsibility, and repair. A valid correction changes the relevant record, rule, authority decision, or transition. It does not pretend the earlier consequence never occurred.

This structure blocks the claim that words possess automatic or mystical force. The symbol becomes consequential only because an operative system interprets it, recognizes an authority, and executes a path capable of changing state.

## Accessibility and implementation

The public diagrams are semantic HTML and CSS with ordered lists, headings, explicit branch labels, and full text equivalents. They remain readable without client-side JavaScript and collapse from a horizontal desktop sequence into a vertical mobile sequence.

The diagrams use the website's existing typography, spacing, color, and component conventions. No image-only text or unexplained visual edge carries essential meaning.
