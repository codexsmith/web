# Projection legibility contract

Boundary First UX treats World, Evidence, and Process as lawful projections of one stable content object. A visitor should not need prior knowledge of the doctrine, hover-only help, or a tutorial modal to understand what changing projection will do.

## Stable identity, alternate representation

Changing projection does not create a new object. It changes which representation of the current object is foregrounded.

- **World** exposes primary content, containment, context, and ordinary traversal.
- **Evidence** exposes standing, provenance, sources, claim boundaries, lineage, and typed relations when that projection is available.
- **Process** places the same object inside the Boundary First operating sequence.

At the Lab root, Process is presented as **Timeline** because the lawful root projection is institutional development history rather than a local operating-process view.

## Visible control vocabulary

Every available projection control carries two visible layers:

1. the stable projection name; and
2. a terse operational purpose.

Current non-root purposes are:

- World — `Content · context`
- Evidence — `Standing · sources`
- Process — `Operating sequence`

The root adapts those purposes to its institutional role:

- World — `Public regions`
- Evidence — `Founder provenance`
- Timeline — `Development history`

The longer projection descriptions remain available to assistive technology and hover titles, but they are no longer the visitor's only explanation.

## Availability

Projection legibility must not imply projection availability. Evidence remains absent from objects that cannot lawfully satisfy the Evidence representation.

The control therefore explains only projections actually returned by the existing availability resolver.

## Transport failure

If a visitor carries a projection toward an object that cannot admit it, the separate projection-transport boundary rule still applies: the fallback must be explicit rather than silent.

Legibility does not change that rule and does not manufacture missing evidence.

## Responsive projection

The explanatory vocabulary remains visible in the compact control on smaller screens. The UI may reduce typography and spacing, but it should not regress to unexplained labels solely because the frame is narrower.

## BFUX invariant

> A projection selector is part of the representation contract. Its available transitions should explain the kind of representation they produce before the visitor has to take them.

This keeps the frame compact while making projection choice inspectable rather than requiring doctrine memorization.
