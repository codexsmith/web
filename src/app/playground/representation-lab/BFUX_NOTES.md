# Representation Lab · BFUX Notes

## Current public role

`Same World, Different Reasoner` is no longer treated as a raw research dashboard. It is a front-page-quality introductory Boundary First Labs experience: a visitor is taught the representation-first idea before the full WORLD-01 apparatus appears.

## Guided entry sequence

The entry experience is deliberately gated and numbered.

1. **Choose the job.** The visitor first changes what the agent is trying to accomplish.
2. **Choose how it reasons.** Reasoning methods are introduced in plain language, with technical names retained as secondary labels.
3. **See what the model gets.** The visitor sees what information is included, excluded, and what kind of output the setup produces.
4. **Load WORLD-01.** Only after the first three choices are legible does the full apparatus render.

After Step 01 advances, the large Playground introduction collapses into a compact identity strip. Completed wizard stages likewise collapse into summaries so the visitor's vertical attention follows the active stage.

## Live setup module

Once WORLD-01 is loaded, the old independent Reasoning Controls + Question Controls stacks are replaced by one explicit **LIVE SETUP** module.

The key BFUX distinction is object-versus-control:

- **ACTIVE SETUP** is the object being changed. It visibly contains the selected **JOB** and selected **METHOD** as two mounted modules.
- **CONTROL A · Change the job** is the input bank that changes the question.
- **CONTROL B · Change how it reasons** is the input bank that changes the computational treatment of the same maze.
- Selected controls are strongly keyed to their corresponding mounted module and labeled `SELECTED`.
- Job uses the blue/information family; method uses the Research-violet family. The difference is categorical, not decorative.
- A pairing module reports `NATURAL FIT` versus `EXPERIMENTAL PAIRING` in beginner language.
- The current job's required information is condensed into a single requirement strip immediately below the controls.

This replaces the previous screen where two visually similar rows of buttons sat above a third row of question/model metadata. The new hierarchy is intended to answer, at a glance: **what am I changing, and which controls change it?**

## Progressive disclosure

Secondary or research-heavy machinery remains available but does not compete with the primary introductory path:

- Assumptions + representation diff live in the Secondary Analysis Bay.
- Feature-Q compression appears as an Advanced Experiment only for MDP mode.
- Particle-budget approximation appears as an Advanced Experiment only for Bayesian mode.
- Route-memory deletion is an Advanced Test.
- The multi-method comparison rack remains available as an advanced comparison surface.

## Physical visual grammar

The apparatus uses the site's physical BFUX system rather than generic cards:

- hard-edged mounted faceplates;
- recessed wells and rails;
- visible categorical signal strips;
- small fastener/instrument details inherited from the Lab Machine skin;
- serif object titles with mono instrumentation labels;
- shallow signal glows rather than broad decorative gradients;
- semantic colors remain semantic: green/valid, amber/attention, red/defect, blue/information, violet/Research family.

## Interaction contract

The world identity remains fixed while task, representation, assumptions, and inference machinery change. The frontend should never imply that a button changes WORLD-01's underlying geometry when it only changes the question or representation applied to that world.

The introductory path should remain understandable without prior knowledge of Boundary Theory, Representational Mechanics, AI terminology, or the Berkeley Pac-Man coursework lineage. Technical language can become more explicit only after the visitor has acquired the concrete mental model through interaction.
